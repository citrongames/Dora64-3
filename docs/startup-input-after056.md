# Иногда нет управления уже на заставке, после056

2026-10-07. База main9172aaf, последний EXE056. Пользователь подтвердил
исправление анимации после белого фейда. Новый симптом: иногда с самого запуска
нельзя стартовать с заставки ни клавиатурой, ни геймпадом; Esc-меню порта работает.
По словам пользователя, похожее бывает с этим ROM в эмуляторе. По его просьбе
исследование выполнено по коду игры, без требования воспроизвести сбой или дать лог.

## Original: отсутствие восстановления подключения

- 800301B0 вызывает osContInit/SetCh4 и 8003C1B8 (dora3_controller_status).
- 8003C1B8 выполняет StartQuery/RecvMesg/GetQuery и обновляет mask801A48B4.
  Для каждого порта требуются type bits1/4 и нулевая ошибка; иначе бит снимается.
- 80030324 (dora3_controller_read) при отсутствии bit0 немедленно возвращается:
  ни повторного status query, ни чтения кнопок. 80030380 также пропускает порты
  без mask. Нулевой mask становится устойчивым состоянием.
- Все прямые Original callers8003C1B8: init800301B0 и поиск периферии8003CF64.
  У последнего callers:8003D04C,8003D110 и update специальной миниигры801C94D0.
  Title/intro статус не обновляют.
- 8003D110 при неудаче инициализации периферии ставит800DAD20=1. Обычный
  controller_pak_tick8003D39C при этом сразу возвращается; повторная попытка
  8003D04C недостижима. В результате неудачный стартовый query может навсегда
  оставить игру без кнопок, даже когда устройство уже отвечает. Анимация и
  переходы, не требующие ввода, продолжаются.

Исправление в общем resident entry80030324: если bit0 отсутствует, перед
исходным чтением вызывается настоящая8003C1B8. Успешный query восстанавливает
mask, далее работают исходные чтение/проверка ошибки/accumulator/latch.
При реально отсутствующем устройстве mask остаётся нулевым, следующие VI
повторяют попытку. Подключение не подделывается, кнопки не синтезируются,
игровые locks не снимаются. Вызов использует копию recomp_context и свободную
область гостевого стека до prologue80030324; регистры исходного вызова сохранены.
Hook подключён через уже существующий общий dora3_trace entry, во всех FPS
режимах и сценах. Изменять generated C или SDK для этого не требуется.

Дополнительно разобраны title801BCEF8/801BCCA8 и intro801C0BBC: оба выбирают
порт0 и проверяют Start/A маской9000. Title init801BCDB0 обнуляет transition
и age; intro thresholds конечны (20/30/50/90), age насыщается65535.
Основания ломать эти таймеры или обходить переходы не найдено.

## Порт: независимые кнопки вместо общей блокировки

В port_input.cpp game_release ожидал одновременно neutral всех клавиш и всех
кнопок/полуосей (порог0.01 после deadzone). Флаг устанавливался при меню или
недоступном фокусе/background input. Один удерживаемый контрол/дрейф мог
блокировать весь N64 input, включая независимую клавиатуру; Esc работал до
этой проверки. keyboard_release в live_io аналогично блокировал все клавиши.

Теперь подавление хранится отдельно для каждой клавиши/кнопки/полуоси до её
собственного отпускания. Новые независимые нажатия проходят. UI/capture
получает исходный PhysicalInput, игра — отфильтрованную копию под тем же mutex.
Фокус, меню, bindings и deadzone сохраняют своё назначение. Добавленная ранее
диагностика INPUT HOST/GUEST удалена: исправление не зависит от сбора логов.

## Границы вывода и статус

Оба механизма доказаны статическим разбором. Точный триггер редкого запуска
пользователя не установлен: порт обычно всегда объявляет виртуальный controller0,
поэтому нельзя утверждать, что именно стартовый query был виновником того случая
или что в эмуляторе причина точно совпадает. Исправлены найденные устойчивые
блокировки, а не объявлена выполненной игровая проверка.

Тесты/fixtures/CPU checks не создавались и не запускались. Игра, эмулятор и GPU
не запускались. ROM/dependencies/generated C не менялись. Новый EXE не запрошен.

Изменённые port_input/live_io/startup_runtime скомпилированы GCC C++20 -O2
в отдельные объекты; без link и исполнения.
