## Поведение

В Native непрерывные координаты, скорость/гравитация, доказанные повороты,
наклоны, масштаб, прозрачность и время моделей получают выбранный Manual dt.
Используются исходные математические операнды и уравнения, включая sinusoidal
phases, подход к цели и конечные ограничения. Сохранённые пары поз не
используются как универсальная замена расчёту.

Wait/counter, RNG, contact, quest/story, выбор/seek клипа, создание и удаление
выполняются в исходном порядке Source. Математический proposal продолжается
только если его итог не был заменён настоящим init/reset/floor/terminal store.
Original20/30 и исходный ABI/ROM identity сохранены.

Test133, Kaiten button527/glass528 и Gondola564 используют математическую
траекторию родителя в Source порядке обхода пула. Поздний родитель сохраняет
предыдущий период; новый lifetime или связь не может продолжить чужую позу.
Gondola повторяет только доказанный чистый расчёт матрицы и локальных якорей.

Door109 добавляет доказанную долю своего перемещения к действительному
положению игрока. Собственное движение игрока не заменяется сохранёнными
координатами. Lifetime/epoch и реальные внешние записи защищают повторное
использование слотов, переключение сцены и смену решения в середине периода.

Смысловые имена и scoped register descriptions закреплены в
recomp/decomp-symbols.json. Каталог и адресные соответствия генерируются вместе
с кодом; исходные символы ABI, function pointers и canonical C проверяются.

## Проверки и границы

Новый Source replay сравнивает все292 ROM-варианта с frozen043 и текущим
Original, затем с Native60/73/120/144/165/360 при Source20/30. Каждый сценарий
получает свежую память, реальные constructors/parser/contact/retirement,
96 Source периодов либо реальный handoff сцены, паузу, внешнюю команду
и zero-dt проверки. Для585 запрос перехода и прекращение старого pool
проверяются по BA0F4/BB080 и шести request globals. В отчёте
перечисляются достигнутые состояния, а не объявляется охват всех ветвей.

Модели, клипы, геометрия комнаты, ресурсы и звук в CPU fixture синтетические.
Для EV типов без найденного штатного FFF0 program явно применяется
синтетическая программа с настоящим Source parser. Это не проверка всех
оригинальных постановок, script branches, сюжетных условий и уровней.
Настоящий контакт игрока с движущейся платформой, внешний вид двери и
плавность объектов в уровнях проверяет пользователь. Игра/renderer/GPU
локально не запускаются.

Завершённые полные варианты сохраняются только с checksum исполнявшегося
теста/логов, точными compiled dependencies и доказанной неактивностью
исправленной ветви для сохранённых сценариев. Частичный вариант повторяется
целиком. После ошибки повторяются её область и затронутые зависимости;
независимый PASS сохраняет фактическую execution provenance.
