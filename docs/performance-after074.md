Фактический Windows CMakeCache/build.ninja: RelWithDebInfo; frontend иRT64
собраны /Zi /O2 /Ob1 /DNDEBUG. Это оптимизированная сборка с символами, неDebug.
В RT64/common/rt64_common.h макросы RT64_LOG_OPEN/PRINTF при NDEBUG пусты,
поэтому подробная запись графических команд этим механизмом отсутствует.
Включены DORA3_PROFILE и собственные per-task/PCM/audio/controller журналы.
Они добавляют расходы, но отдельной длительности их записей пока нет.
Признать их единственной причиной или обещать заданный FPS после отключения
по текущим данным нельзя.

В тяжёлых участках основной оставшийся измеренный расход находится в graphics
producer stage RT64Parse: примерно6–8мс thread CPU на кадр, GPU порядка0.3мс.
Это обёртка send_dl, включающая подготовку, HLE interpreter, fullSync/texture
work и ожидания очередей, финальный собственный log. Нельзя назвать внутреннюю
операцию без разделения этих расходов. Профили вложенных main stages не суммировать.
