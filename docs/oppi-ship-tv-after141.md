# Подарок птицы, ТВ и корабль

## test142: подарок Oppi, стык ТВ и диагностика Sentoutei

Птица Oppi316 (overlay12FD90) в flight101/F94C создаёт E70E0 слот0
из дескрипторов801FC770/C78C/C7E0: предметы111/112/114. Этот allocator
ищет слот после родителя. Подарок в state2 следует через EBAD4 по матрице
родителя и смещению(0,-70,0); FBB0 снимает связь, затем идут исходная
инициализация падения, gravity2/предел-48 и переход к state1.

Native pickup_attachment_parent ранее принимал только flash130. Добавлена
строго ограниченная связь с живой Native-птицей316 в101/phase0: её slot0,
встречный индекс7E и индекс самого подарка должны совпадать. Сохранены
порядок слотов, lifetime, Source-born acquisition, исходные callback/contact
подарка и проверка конечности позы. Геометрия EBAD4 теперь получает текущую
Native-позу птицы; draw читает текущие координаты actor, включая тень.
Source сохраняет рождение, выбор подарка, отсоединение, коллизию и посадку.

TV375: левая заливка до x4 вместо x1 перекрывает расхождение границ
прямоугольника и спрайта. Первые пять колонок исходного CI4 bitmap4DB
(ROM352670) целиком имеют RGBA16 0843 — тёмная кайма. Заливка рисуется
перед исходным спрайтом; его размер, открытое изображение и правая маска
не меняются. Original-режим не получает новую игровую логику.

Космический корабль идентифицирован как Sentoutei3/368: ROM размещает
четыре368 вместе с шестью турелями382 в сцене301. Исходный state1 вызывает
импульс50/gravity5 и при vY<=0 переходит в3; chase содержит поворот pitch,
ограничение по homeY и probe пола с offset-100. Эти пути уже есть в Native.
Причина наблюдаемого избыточного взлёта пока НЕ установлена, поведение
корабля не менялось. Пользователь разрешил диагностический билд:
SHIP entry/command/motion-end пишет XYZ, скорости, ускорение, pitch/yaw,
состояния/счётчики, Source/Native clock, записанный gravity/projection,
несовпадение с ожидаемой позой. Ограничение40000 строк на процесс;
вход Original также наблюдается. Никаких дополнительных игровых вызовов.

Windows test142 — инкрементальный Release, CrashLog ON для согласованной
диагностики, общие Diagnostics и GraphicsProfile OFF, без PDB/CodeView.
Повторно используется генерация141; предыдущий фикс огня сохранён.
Игра/тесты/CPU checks/GPU не запускались; проверка подарка, ТВ и журнал
корабля ожидаются от владельца. Коммит/push не разрешены.


## test143: сборка без журналов; поведение кораблей подтверждено в ROM

Владелец воспроизвёл зависание пары Sentoutei3/368 сначала в Manual,
затем в Original FPS порта и отдельно в оригинальном ROM в эмуляторе.
Оба журнала142 показывают повторную реакцию контакта в chase3:
physical36 остаётся1, после торможения и семи шагов восстановления
скорость продолжает уходить ниже нуля; pitch чередуется0/185, Y растёт.
Исходный код F3A0/F534/F5B8/F600 соответствует этой последовательности.
Это не установленная регрессия Native; игровая логика кораблей НЕ изменена.
Разбор журналов: research/sentoutei-test142-review.json.

По прямой команде владельца test143 собирается без журналов:
Release, CrashLog/GraphicsProfile/Diagnostics OFF, без PDB/CodeView.
Сохранены исправления141/142: рост огня TwinFace, следование подарка Oppi
и левая кайма ТВ. Повторно используется генерация startup-fire141-v1.
Игра, эмулятор, тесты, CPU checks, renderer/GPU агентом не запускались.
Игровая проверка исправлений141/142 ещё не заявляется. Коммит/push ожидают
отдельной команды после проверки. Старые EXE и пользовательские файлы сохраняются.
