# Windows test-002 — ограниченный старт

Это исследовательская сборка x64/RT64 Automatic, ещё не игровой порт. Windows EXE
агентом не запускался: картинку, ввод и звук проверяет пользователь.
Предыдущий Windows test-001 показал Epoch и завершился на заданной границе
801B54C8 (код77). Это подтверждено журналом пользователя; fade не успел получить
следующие кадры. В test-002 добавлен связанный пакет scene1: переход, смена
оверлея, init/update/draw и их зависимости. Его визуальный результат пока неизвестен.

## Запуск пользователем

Папка всех сборок: `D:\Games\DoraRecomp3\testbuild`.
Запустить `Dora64-3-test-002.exe` двойным щелчком. Рядом нужен собственный
`Doraemon 3 - Nobita no Machi SOS! (J) [!].z64` (Japan N3DJ rev0).
SHA-256: `410f99bdd58795639da272c9be9d1ab8c35b61f24f7c1fb92f7e83e1069a2602`.
EXE получает свою папку через GetModuleFileNameW; другие папки не просматривает,
параметры с альтернативным путём не принимает. ROM в пакет не включается.

Клавиатура: WASD — стик, Z/X — A/B, Enter — Start, пробел — Z, Q/E — L/R,
стрелки — крестовина, IJKL — C. Первый SDL GameController тоже подключается.
Оригинальная проверка контроллера сохранена, порт 0 доступен с клавиатуры.
Переназначения и меню пока нет.

Это всё ещё исследовательская сборка: неподдержанный вызов завершит её с
диагностикой. Максимум1800 graphics tasks или120 секунд после настройки RT64.
Нужно проверить прохождение Epoch, белый fade и появление вступительной 3D-сцены.
Успешная компиляция не означает, что все три этапа уже работают.

При проверке достаточно сообщить, что появилось, были ли искажения, и передать
`logs/<время>/runtime.log` и `stdout.log`. Подпапка `state/resources` содержит
извлечённые данные игры; её и ROM не включать в публикуемые материалы.
Сохранения этого этапа изолированы в каталоге запуска и не являются постоянными
сохранениями будущего порта. Слышимого игрового звука пока не подтверждено:
ранее аудиоустройство открылось, но полученные PCM-отсчёты были нулевыми.

## Сборка без запуска

CPU и audio RSP сначала генерируются в WSL по `docs/reproduction.md`.
Для текущего этапа CPU output — `build-local/startup-v44`, audio output —
`build-local/audio-rsp-v1`. На Windows нужно перенести отслеживаемые исходники,
изолированное дерево `build-deps` без `.git` и только эти два generated-каталога.
ROM, run-каталоги, resources и saves в перенос не входят. Относительная структура
сохраняется; CMake сверяет входные и generated SHA-256 с generation-receipt.json.

Требуются Visual Studio 2022 C++ x64 с Windows SDK, bundled CMake/Ninja, Python3.
В PowerShell из корня подготовленного проекта:

```powershell
./tools/build_windows.ps1 -Python 'C:/path/to/python.exe' -Fresh
```

`-Fresh` удаляет старый CMake cache через `cmake --fresh` (нужен CMake 3.24+),
что необходимо после неудачного определения компилятора. Конфигурация
RelWithDebInfo: MSVC `/O2 /Zi /EHsc`, динамический CRT. Скрипт не запускает игру.
SDL2 2.26.3, DXC/DXIL взяты из уже закреплённого RT64; библиотеки не изменялись.
Упаковка `tools/package_windows.ps1` копирует только явный список EXE/DLL и
инструкцию, пишет SHA-256. Полную папку testbuild архивировать нельзя: там ROM.

## Известные ограничения

1311 оригинальных функций, 43 SDK mappings; покрытие ветвей и оверлеев неполное.
SP completion после разбора display list не доказывает завершение асинхронного
чтения памяти renderer/GPU. Исследование lifetime остаётся отдельной задачей.
Общие исправления Dora64 сохранены в pinned зависимостях; адреса/камера/HUD и
прочие патчи первой игры не переносились. Android live build ещё не готов.

Выбор API совпадает с Dora64: `GraphicsAPI::Automatic`. В Windows RT64 сначала
выбирает D3D12, под Wine — Vulkan; сохранены fallback при ошибке создания device
и driver compatibility workarounds. Linux/Android — Vulkan. Конкретный выбранный
API логируется после setup. Основание: Dora64 src/rt64_render_context.cpp,
RT64 common/rt64_user_configuration.cpp и hle/rt64_application.cpp.
