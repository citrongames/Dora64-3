# Нативный старт: проверенный рубеж 2026-09-27

Это диагностический frontend без окна и вывода PCM. Linux x86-64 / WSL2,
GCC 15.2, RelWithDebInfo. Он использует закреплённый N64ModernRuntime из
отдельного build-deps; код библиотек и их pins не изменены.

## Подтверждено исполнением

- Оригинальные entry → bootproc → idle → main выполняются нативно.
- Runtime создаёт и переключает игровые потоки; scheduler 0x800268A8 запущен.
- Пройдены исходные инициализации VI, графических task buffers и SI/controller
  queues. В этой диагностике контроллеры отключены; Controller Pak ветвь
  с подключённым устройством и игровой ввод ещё не проверены.
- DMA wrapper 0x8002730C использует настоящий runtime osEPiStartDma и очередь
  завершения. ROM 0xFA1FA0 → RAM 0x800DD8F0, 0x1C760 байт; ROM 0xFBE700 →
  RAM 0x800FADE0, 0x2580 байт. Оба диапазона совпали с ROM побайтно **до** релокации.
- Оригинальная релокация инструментального и секвенсорного банков выполнена.
  Создан пул DMA для звуковых данных. Вызван osAiSetFrequency(22050).
- Достигнут конструктор синтезатора 0x8004C4DC; следующий непроверенный вызов
  0x80051B88 завершил программу с кодом 77. Аудиопоток id3 пока не запущен.

recomp/startup.json содержит 45 отобранных оригинальных функций и 28
идентифицированных SDK entry points. Размеры и роли проверялись по коду ROM,
call sites и SDK reference. Вся функция не считается протестированной только
по факту прохождения одной ветви. Названия dora3_* обозначают исследованные роли,
а не восстановленные оригинальные символы.

Генератор обнаруживает неизвестные прямые JAL и создаёт для них явную остановку.
Пустых заглушек успешного возврата нет. Таблицы косвенных вызовов и полный набор
оверлеев ещё предстоит разобрать; регистрация сейчас охватывает resident subset.
ROM section в генераторе включает resident code/data до 0x59E80, но кодом
рекомпилируются только перечисленные функции, не весь диапазон.

## Звуковой RSP

Указатели независимо найдены в аудиопотоке 0x8004E044 и конструкторе задачи
0x8004DD4C; затем проверены загрузочный RSP-код и таблица переходов.

| Роль | ROM | VRAM / IMEM | Размер |
|---|---|---|---|
| RSP boot | 0x3DA20 | 0x80062620 | 0xD0 |
| Audio text | 0x3DAF0 | 0x800626F0 / 0x1080 | 0xE20 |
| Audio data | 0x53F40 | 0x80078B40 | полный размер пока не закреплён |

SHA-256 audio text:
`14e3b245e8cd4e0bdf4cbb864af82d1ccba6d3d3ff33f73cb52c5821a76f30fc`.
Текст побайтно совпал с audio text первой игры после независимого определения
местоположения; это не доказывает совпадение CPU-аудиодвижков.
16 u16 dispatch targets читаются непосредственно из audio data +0x10.
RSPRecomp успешно сгенерировал C++, GCC скомпилировал его в object file.
Настоящая RSP-задача пока не наблюдалась, PCM не получен, слуховой проверки нет.

## Уточнение CPU/RSP

Предварительный диапазон disassembler 0x1000..0x3E910 включал RSP bytes.
Теперь граница начала RSP boot установлена как 0x3DA20. Автоматические границы
функций остаются кандидатами: например, entry с tail jump анализатор объединял
с соседними функциями; в рабочем metadata сохранён проверенный размер 0x3C.
Это основание не принимать всю автоматически построенную карту без проверки.

## Следующая работа

1. Разобрать конструкторы фильтров и callback tables синтезатора; дойти до
   запуска аудиопотока и фактического OSTask, не пропуская инициализацию.
2. Подключить проверенный audio RSP, затем вывод PCM в SDL с исходным темпом.
3. Продолжить main до загрузки стартовой сцены, решить известный PI случай
   0x3FF/0x400 и регистрацию взаимозаменяемых оверлеев.
4. Подключить RT64 с установленным сроком жизни памяти задачи, получить первый
   кадр и проверить оригинальное управление. Затем переносить frontend на
   Windows/Android; прежняя cross-platform проверка относится только к boot-probe.

## Источники и воспроизводимость

- Исходный ROM пользователя, проверяемый по recomp/rom.lock.json.
- Закреплённые исходники runtime и N64Recomp из dependencies.lock.json и
  tools/n64recomp/lock.json; чужие игровые адреса не используются как доказательство.
- [ultralib reference](https://github.com/decompals/ultralib/tree/e24c836796df4bf520ff8b11a5c9d2cea3a66cbd),
  commit e24c836796df4bf520ff8b11a5c9d2cea3a66cbd, только сверка API/структур.
- [spimdisasm](https://github.com/Decompollaborate/spimdisasm), версия 1.42.4
  с rabbitizer 1.16.2, только подсказки анализа. Для генерации/сборки не требуется.

Команды — в reproduction.md. Результаты исполнения сохраняются локально в
build-local/run-startup-*/result.json и runtime.log. Нельзя включать state/ROM,
generated C/RSP, дизассемблирование или извлечённые ресурсы в исходный архив.
