# Длительная проверка игрока и мира: сохранение точного результата

Полный player/world прогон перед043 завершился PASS за5008.47 секунд
(1 час23 минуты28 секунд, включая подготовку и компиляцию). Все28 CPU checks
перед043 прошли. Четыре параллельные группы выполняли одинаковый широкий
набор сценариев для двух камер и двух исходных частот. Каждая группа
сохраняла шесть Native FPS60/73/120/144/165/360 и все Original, Native60,
полные RAM/context/resource/command сравнения и финальные C++ assertions.
Длительность групп:4126.21 /4707.67 /4096.51 /4762.70 секунды. Процессы
работали, признаков зависания не было; журнал почти не показывал прогресс.

Теперь tools/check_native_player_update_partitions.py сначала подготавливает
тот же C/C++ и seed, затем проверяет сохранённый результат каждой группы.
Ключ включает790 выбранных функций, сгенерированные dispatch/fixture headers,
seed, настоящий список всех headers из compiler dependency scan, содержимое
компиляторов/linker/assembler, startup objects, runtime/sanitizer libraries,
флаги и архитектуру. Имена каталогов generation нормализованы; содержимое
каждого выбранного файла остаётся в ключе. Первый запрос текущей версии
обнаружил отсутствие cache и отказался что-либо запускать в режиме проверки.

Для заполнения cache сохранены четыре настоящих завершённых группы043.
Перед переносом подтверждены полное доказательство28 checks, SHA исходного
report/runner, byte-identical существующие generated inputs/seed, проектные
dependencies по завершённым CPU proofs, чистые dependency pins и неизменность
системных/compiler файлов после компиляции. У каждой группы сохранены
исполненный binary, stdout/stderr, исходная generation и report/commit hashes.
Исходный отчёт043 и его Windows proof сохранены без изменений.

Если точные входы совпали, дорогой subprocess не запускается. Если изменилась
зависимость, повреждён log/binary/record, группа не закончилась или вернула
ошибку, требуется новый прогон. Успешные группы публикуются по отдельности и
атомарно: после ошибки повторяются только недостающие группы, остальные
остаются с фактическим происхождением. Failed попытки не становятся PASS.
Изменение входов во время компиляции/исполнения также запрещает публикацию.
Код и все24 сочетания исходных oracle сохранены; охват не сокращён.

Повторная проверка всех точных входов и четырёх сохранённых результатов заняла
около10 секунд вместо нового часового исполнения. Это проверка ранее
завершённого результата, а не новый полный runtime replay. Первый прогон
при изменении player/world зависимостей по-прежнему может быть долгим.
Cache устраняет ненужные повторения и потерю успешных групп после ошибки;
ускорение нового широкого replay пока не измерялось.

В обычном pre-build механизм включён автоматически. --force-run явно
запускает все группы заново. --verify-cache-only проверяет сохранённый
охват24 settings и отказывается компилировать/исполнять oracle при cache miss.
Его отдельное доказательство — research/native-player-update-cache-check.json.
Проверки повреждения/инвалидации/ошибки настоящего subprocess —
tools/check_native_oracle_cache.py и research/native-oracle-cache-check.json.
Эта короткая проверка механизма использует отдельную миниатюрную C++ fixture,
не доказывает новое поведение игры и не запускает игру/renderer/GPU.

043 собрана и упакована до изменения оркестратора. Её полные CPU/Windows
отчёты относятся к реализации и версии проверок в commit38f53fb. Новая
инфраструктура cache проверена отдельно; новый EXE для её изменения не нужен.
Следующий крупный выбранный блок всё равно проходит полный connected набор
перед сборкой, с честным указанием свежих и сохранённых exact-input результатов.


## Блок6: исключён повтор общей NPC матрицы

Полный player proof сохраняет четыре camera/source-rate группы, все24 settings
и шесть FPS. Общая функция check_npc_action_contacts имеет собственный fresh
RDRAM/allocator/model setup и уже перечисляет оба Source divider, все шесть FPS,
двенадцать NPC kinds и все3192 исходных сценария. Раньше одна и та же матрица
повторялась в каждой из четырёх процессов. Теперь она полностью исполняется
один раз в group0; groups1..3 проверяют только свои шесть settings. Агрегатор
требует ровно3192 NPC cases, ровно один полный NPC PASS,24 суммарных settings и
все прежние scoped assertions. Derived source/group signatures входят в exact
cache key; старые четыре proof provenance не превращаются в новый запуск.
Это сокращает одинаковую работу, не убирая ни одного самостоятельного сценария.
