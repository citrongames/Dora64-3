## Найденный служебный расход

На5x около2.80млн вызовов dora3_trace/сек, на1x0.58млн/сек, на паузе5x1.28млн/сек.
Эта функция вызывается при входе в исходные функции, включая мелкую модельную
математику и геометрию. Каждый вход линейно просматривал49 записей оверлеев.
Если запись совпадала, проверка зависимостей заново просматривала91 запись.
Проверка первого входа также повторяла unordered_set lookup по(ROM,VRAM).
Native subdivisions умножают эти расходы, хотя таблицы ROM и зависимостей
вообще не меняются между входами.

Ранее trace_sample_1_in_64 имел observed_calls=calls, sampled=false в stage
при наличии отдельного trace_calls на строке. Автоматическая агрегация sampled
stages поэтому недооценивала trace. В устойчивом5x измеренные5.99мс/сек выборки
дают примерно383мс/сек после масштабирования по всем входам. Это оценка wall
body time, НЕ точное CPU attribution: периодическая1/64 выборка может совпадать
с повторяющейся последовательностью функций; накладные расходы измерения тоже
входят в sampled body duration. Вложенные scopes не складываются.
У main Native update CPU около257мс/сек, frame158мс/сек; parser отдельно379мс/сек.
Большое число full-pool calls само по себе не доказывает, что все границы лишние.
Старые результаты про actor-local periods, рождения, AI/child ordering сохраняются.

## Исправление074

startup_runtime.cpp строит constexpr open-addressed индекс ROM по существующей
сгенерированной таблице и компактные ordered spans зависимостей. Это неизменные
описания, не кэш разрешений. При КАЖДОМ входе загрузка владельца и необходимых
родителей читается из тех же atomic<bool>. Те же atomic generation tokens,
все события verified DMA/load/unload/reset и ошибка85 сохраняются. Generation
так же возвращает max собственного и рекурсивных родительских tokens.

Флаг первого диагностического входа — thread-local bitmap, отдельный для
resident и каждого ROM overlay. Границы вычислены из текущего section_table,
без придуманных адресов. Одинаковый VRAM разных ROM не делит флаги. Unaligned,
неизвестные и выходящие за metadata ranges входы используют прежний key/set.
Как раньше, reload/reset не обнуляет отметку уже увиденной функции потока.
Проверка загрузки и все special trace adapters исполняются независимо от этой отметки.

В profiler074 trace observed_calls записывается из уже существующего счётчика,
без дополнительного atomic increment; выборка использует тот же ordinal hash,
что другие sampled stages, чтобы уменьшить совпадение с периодическим порядком.
Формат имени/частота1/64 сохраняются. Это исправляет интерпретацию профиля.

Игровая логика, все границы SimulationTimeline, ввод, AI, столкновения,
birth/clip/parent events, дальность/ёмкости и сгенерированные тела функций
не изменяются в074. Предложение coalesce unchanged input не применено.
Статический diff074 ограничен runtime registry/diagnostic metadata и profiler.
Windows incremental compile/packaging выполняется после готового изменения;
успешная компиляция не подтверждает60FPS или правильное поведение игры.
Commit/push только после проверки и команды пользователя.
