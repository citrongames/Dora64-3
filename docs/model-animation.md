# Общая модельная анимация: подтверждённый контракт и интеграция

2026-09-29. Анализ закреплённого ROM, а не перенос структуры Dora64.
tools/analyze_model_animation.py воспроизводимо проверяет4778 функций50 секций,
28 общих API и прямую достижимость из установленных update/draw callbacks.
research/model-animation-inventory.json содержит адреса, хэши, вызовы и границы
доказательств; игровых данных/инструкций в нём нет.

## Масштаб общего подключения

| Операция | Прямых вызовов во всём известном коде |
|---|---:|
| Выбор клипа через object_select_clip8002A328 | 752 |
| Чтение окончания через8002A3B0 | 362 |
| Чтение времени через8002A3F8 | 129 |
| Чтение длительности через8002A3D4 | 65 |
| Seek через8002A41C | 48 |
| Pause через8002A4A4 | 90 |
| Clamp через8002A454 | 222 |
| Вычисление позы и advance через8002A1B8 | 36 |

Это call sites, не число моделей и не процент готовности. Большая часть поведения
сходится в resident API: не требуется752 отдельных патча. Однако простой множитель
у36 вызовов не сохраняет события у362 читателей и сравнения времени у129 читателей.
Прямые closure показывают в том числе model API из draw-путей; это кандидаты на
разделение, а не доказательство, что все вызовы происходят каждый кадр. Косвенные
callbacks и alias-записи остаются отдельной границей анализа.

## Подтверждено по оригинальным функциям

Model — объект0x84 байта.8003B560 создаёт его и дерево костей; object+0x74+index*4
содержит указатель.8002A170 сначала освобождает текущие channels через8003B744,
затем8003B6BC устанавливает новый clip: +0x04/+0x0C base, +0x18 channel descriptors,
+0x1C keyframe descriptors, +0x2C count, +0x60 channel index array, +0x64 time=0.
Flags+0x7C &=0xF4 очищает clamp/end/pause, остальные биты сохраняет.
Даже тот же clip по тому же адресу — новое состояние, а не продолжение старого clock.

8002A1B8 сначала вызывает800393C4 (поза), затем8003948C (advance). Channel evaluator
читает +0x64 как float:80038FA8 — линейная кривая,80039078 — кубическая с касательными.
Это вычисление исходной анимации в заданный момент; RT64 для него не нужен.
Bone channels записывают transform выбранного узла через80038A88/800389F0.

Morph8003931C→80038D58 читает bank index801A9544 и пишет в model+0x6C+bank*4.
80038BC8 создаёт ДВА буфера размером model+0x30 *16 и копирует исходные вершины.
80038C58 передаёт оба на deferred free и обнуляет указатели. При переносе позы
на native-кадры bank должен совпадать с FrameTicket; нельзя рассчитывать morph в
ещё занятом банке или освобождать его до завершения чтения кадра.

End getter80039544 только читает bit1: чтение НЕ потребляет событие. Несколько
потребителей одного обновления должны увидеть один и тот же результат. Следующий
обычный advance очищает bit1, но пауза/disabled оставляют его; clamp на конце может
сохранять bit1 при повторных updates. Поэтому consume-on-read/FIFO вместо флага
было бы изменением игровых правил. Компонент Animation::consume_completions —
внутренний счётчик пересечений, не готовая замена гостевого getter.

Seek80039564 принимает integer; object wrapper8002A41C сначала trunc float.
Seek меняет время, но не flags; pause/clamp commands поддерживают set/clear/toggle.
Native clock нельзя переинициализировать только по отличию time: seek в то же
значение и смена клипа по тому же указателю требуют явной границы команды.

Destroy8003B77C снимает morph, channels, дерево и сам model; allocator может вернуть
тот же адрес следующему model. Внешнее состояние должно включать generation,
сбрасываться на create/bind/seek/destroy/system reset и не удерживать освобождённые
указатели. Rate — аргумент update, не постоянная универсальная3: найдены1/2/3 и
динамическое чтение object+0xCC. Divider сцены также обязателен.

## Следующий цельный шаг реализации

1. Единая регистрация model/clip generation на перечисленных общих API, наблюдение
   rate при исходном update, invalidation на всех командах и teardown.
2. Отделение дискретного event/time состояния, видимого логике, от вычисления позы
   для каждого нового кадра. Getter остаётся недеструктивным; события/seek/смена
   модели выполняются в исходном порядке. Не ускорять весь phase0 dispatcher.
3. Общий проход позы перед build в выбранный свободный bank, включая morph;
   проверка draw-side effects и bank ownership до расширения допуска3D сцен.
4. Движение/столкновения/камера — отдельные общие подсистемы: плавная модель на
  20Hz позиции ещё не означает завершённый native gameplay.

В test-026 model hooks не активированы: этот документ фиксирует проверенную основу
и конкретные точки общего подключения. Нельзя считать частоту3D повышенной на
основании одного этого анализа. Живая реализация этой итерации — общие fade commands.
