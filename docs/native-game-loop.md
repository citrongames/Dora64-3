# Общий native кадровый цикл и карта оставшейся работы

2026-09-29, generation v67, кандидат test-026. Это общая интеграция, но не завершённый
перевод всей игры на произвольный FPS. Все4778 известных оригинальных функций уже
скомпилированы; их количество не является очередью ручного подключения.

## Что подключено один раз для игры

src/native_game_loop.cpp управляет входом, выбором следующего банка, полным
graphics_frame_build8002FF64, публикацией, счётчиком outstanding, сменой Manual,
выходом и ожиданием подтверждений. Общие hooks стоят в resident message loop,
до/после VI-update, до исходного fade_tick, в process-pair replacement и в общих
submit/SP/DP retirement. Кадровый producer и present теперь имеют настоящего
игрового потребителя. Это уже не отдельные несвязанные компонентные протоколы.

Правила допуска отделены в native_scene_policy.cpp. Новая проверенная группа
сцен добавляется в этот реестр, не требует нового message loop или своего scheduler.
Сейчас разрешена image-ветвь scene34 и её белый fade в проверенной state1-ветви: это граница покрытия,
а не обещание native FPS на остальных этапах. Политика требует завершённого init,
стабильных process slots, отсутствия других active callbacks и cross-frame copy.
Замена пары callbacks сбрасывает авторизацию. Неизученные состояния идут Original.

Manual60–360 берётся из существующих сохранённых настроек. Native не включает
RT64 interpolation; вне разрешённых состояний Manual даёт исходную частоту20/30.
Original остаётся прежним, Display сохраняет прежнюю RT64-интерполяцию.
Пояснение в существующем поле меню отражает экспериментальное покрытие, новых
элементов/цветов/раскладок не добавлено.

RT64 использует Original для запрета интерполяции, поэтому старый VSync-policy,
смотревший только на RT64 Manual, ограничивал бы native вывод монитором. В pinned
build-local present queue добавлен независимый запрос native target. VSync меняет
сам present thread. При target выше Hz он отключается; после drain возвращается.
Запрос необязательный, с null default: standalone graphics replay не зависит от
игрового frontend. Исходные зависимости/донор не изменены.

## Общая граница входа и выхода

Вход только после исходного дискретного update (built0, deferred0 и VI counter0).
Entry-pending сначала прекращает новые Original builds/updates, затем ждёт legacy
game count0 И окончание обоих внешних SP/DP callers. Только после этого резервируется
PresentationGate, завершается старый host read и запускается native producer.
Следующее сообщение продолжает handoff без блокирующего ожидания в guest thread.

Native consumer получает копию контекста, обновляет Fade по монотонному времени, вызывает
настоящий общий build/submit и после blocking submit повторяет исходное увеличение
outstanding и переключение банка. VI/input/repeat/rumble/pak/sound остаются на
исходном дискретном пути; исходный fade_tick для активного native fade пропускается.
Пауза/смена режима/неподходящее состояние отменяют будущие wake. До завершения
всех task/game/host-read запрещены Original build/update и освобождение ресурсов.
Process replacement внутри ещё активного native режима — явная ошибка политики,
а не разрешение менять ресурсы с незавершёнными кадрами.

Снимок FPS читается один раз на попытку входа: повторное чтение могло получить0
при одновременном переключении Manual→Original и ошибочно вызвать begin(0).

## Сквозная проверка

check_native_loop.py исполняет27 оригинальных функций: настоящий message loop,
game_retrace_update, process dispatcher, полный graphics build/submit, image draw,
fade и input-repeat helpers. В v67 включён также настоящий scene34_transition,
его fade commands и scene_select; progress-reset state2 остаётся за границей допуска. Hardware scheduling/VI/input sampling/audio/present —
явные synthetic endpoints; GPU не запускается. Проверены задержанный последний
legacy task access при уже нулевом game count, вход,60→73→144→360, пауза, Original,
повторный вход, ровно76 дискретных обновлений и drain до callback replacement после белого fade.
Число native frames зависит от времени выполнения стенда, оно не измеряет FPS GPU.
Отдельный pump-check использует настоящие SP/DP handlers и очередь, включая
отрицательную проверку прежнего раннего retirement. ASan/LSan пройдены.

Исправлена ошибка старого image-only стенда: он использовал decimal31728/12328
вместо hex0x31728/0x12328. Production constants из frame_lights.hpp были правильны;
теперь стенд тоже использует их и проверяет настоящую пару банков. Старый отчёт
не доказывал именно эти адреса. Повторная проверка прошла. Полный loop использует
оригинальную арифметику построения банка, а native consumer — те же shared constants.

Найдено47 установок пар update/draw,3 отдельных slot installs,61 косвенный call,
167 вызовов fade commands,36 общих pose/time wrappers,25 input-select,22 repeat,

константами; это кандидаты, не доказательство всех исполнений/overlay identity.
Граф прямых вызовов сохранён в форме closure-категорий для callbacks. ROM/инструкций
в отчёте нет. Полная карта: timing-inventory.md и research/timing-inventory.json.

Автоматические stores/float ops/branches — подсказки для исследования. Инвентарь
не доказывает семантику физики, чистоту всех draw или отсутствие неизвестных
табличных callbacks. Поэтому процент готовности по числу функций не вычисляется.

shared object/camera update, а не последовательное включение4778 отдельных функций.

## V67: команды fade и результат test-025

Пользователь сообщил: test-025 не вылетел в выполненной проверке, первая заставка
показалась в60FPS. Это ограниченная пользовательская проверка, не полный прогон.

Все пять resident команд fade теперь синхронизируют общий FadeTimeline перед
исполнением. Изменившееся состояние начинает отсчёт в момент команды; no-op
сохраняет дробный остаток. Время до команды не приписывается новому переходу.
Исходный MIPS-код команд выполняется полностью; Original/Display hook ничего не меняет.
При паузе/выходе последнее состояние сохраняется; ожидание handoff не считается
временем игры. Неизвестная запись в управляемый fade выявляется явно.

Белый fade state1 разрешён до counter==1; затем полный drain ДО process replacement.
State2 имеет progress reset и сохраняет прежний fallback. Loader/3D/menu ещё Original.
Проверки: все пять настоящих команд, команда между deadlines, повторный no-op,
смена скорости/направления, команды в один момент; настоящий цикл до76updates.
Полный разбор модельного времени и lifecycle: [model-animation.md](model-animation.md).
