# Диагностическая Windows test150

Владелец проверил test149: все четыре описанных симптома остались.
Правки149 не приняты и не объявляются исправлением симптомов. Дополнительно
сообщён нерастянутый оверлей в финальном бою с каской и слизью.
Пользователь явно запросил сборку с логом и предложил переключения
Manual → Original → Manual как временные маркеры.

## Что записывается

- `MF150 ... FPS_MARKER`: изменение FPS/предела и wide/HUD, монотонное
  время t_us, wall_ms, последовательный номер и segment. Каждое переключение
  перезапускает ограниченные бюджеты подробного журнала. Маркер UI не читает
  гостевую RAM; следующая FRAME привязывает его к сцене на гостевом потоке.
- FRAME/LOOP: фактический Native build/владение, пригодная политика,
  fallback, update/draw callbacks, divider, script/pause/copy/graphics gates.
- BOSS5: реальные callback entries в Original и Native, внутренний интервал,
  уравнения yaw/heading и связь slime с body. POSE до/после настоящего draw
  для Boss5 и финального Boss6, включая локальные/мировые XYZ, углы и матрицу.
- RACE: все четыре участника, скорость/тормоз/проекция/стены, четыре камеры
  и origins до/после draw. RACE_SOURCE/CAPTURE/FIELD/MATH: реальный Source
  capture и дробная публикация, роли, валидность владельца и nonfinite.
- SCRIPT: реальные Source границы, публикация интервала, rebase и несовпадающие
  поля; POSE участников сценария и machine/back, все активные controller slots.
- OVERLAY: достигнутые draw scopes/аргументы/Source caller, роль aspect,
  координаты и режим маски. DL/DL_SUMMARY: ограниченная запись достигнутого
  display list, texture-image адресов, scissors, fills, texture rectangles и
  extended roles. Это чтение реальных команд, без запуска renderer/эмулятора.

Подробные POSE/RACE/BOSS записи ограничены6000 наблюдений на владельца,
этап и segment; DL —240 снимков с шагом0.5s, максимум128 подробных строк
на снимок и16000 прочитанных команд. Пределы обновляются FPS-маркером.
После достижения проблемного места переключить FPS для свежего участка;
несколько секунд Original и затем Manual дадут сопоставимые данные.

## Сборка и проверка

CrashLog ON включает целевой журнал в перечисленных runtime исходниках.
Diagnostics и GraphicsProfile остаются OFF; пользовательские настройки и
место их хранения сохранены. Журнал: рядом с EXE `logs/Dora64-3-test-150-<stamp>-<pid>/runtime.log`.
Обычная Release сборка с CrashLog OFF не выполняет форматирование, чтение
трассы или блокировку журнала. Игровая логика дополнительно не меняется.
Правки149 остаются в диагностируемом состоянии; их эффект опровергнут
проверкой владельца. Коммит/push не выполняются до нового разрешения.
Агент игру/renderer/эмулятор/GPU/тесты/CPU checks не запускает.

Windows Release150 собрана и упакована, код0; новая CPU генерация не требовалась. CrashLog ON, Diagnostics/GraphicsProfile OFF. Определения диагностического режима проверены у всех инструментированных исходников;11 runtime/сборочных файлов и готовый EXE совпали по SHA256. PDB/CodeView отсутствуют;623 существовавших файлов сохранены. Игра не запускалась. Захват владельца ожидается; коммит/push не выполнены.
