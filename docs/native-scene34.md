# Первая 2D-сцена: подтверждённая граница рисования

2026-09-29, ROM из recomp/rom.lock.json, generation v65. Живая native сцена ещё
не подключена. Здесь разделены исполненные проверки и план интеграции.

## Проверено по оригинальному коду

Scene34 init801C0184 выбирает divider3 (20 игровых обновлений при60VI), устанавливает
update801C0088/draw801C012C. Setup801C0014 задаёт hold801C68D0=60 и transition
counter801C68CC=0. Update опрашивает сохранённый ввод и repeat, уменьшает hold;
при его окончании вызывает801BFDE0, которая начинает белый fade и устанавливает
transition counter16. Эти вызовы нельзя повторять на каждый дополнительный кадр.

Draw801C012C строит команды очистки depth/color, затем выбирает ветку по801C68C4.
При0 вызывается801BFF24: настройка texture state8002A724, чтение описателя картинки
из801AEC00+index*20 через80028370 и исходный scaled texture rect8002A844.
800282EC/80028320/8002833C/80028344/8002834C/80028354 только читают заголовок.
Выходные параметры80028370 направлены в локальный стек centered_image.
Depth/color clear здесь записывают display list; это не CPU очистка framebuffer.
Текстура загружается при setup, повторного resource load в image draw нет.

Аудированная ветвь записывает команды DL, его cursor801B1424 и стек. Путь controller
warning801BFE80 вызывает другой текстовый renderer и сюда не включён. Исследование
первой части не использовалось как доказательство поведения этой сцены.

## Исполненная проверка без GPU

tools/check_native_scene34_draw.py извлекает15 настоящих функций из проверенной
генерации; исходные тела и128байт resident constants хранятся только в ignored
build-local. Текстуры и ресурсы игры не копируются: заголовки и память синтетические.
Единственный SDK endpoint — прямой KSEG0 osVirtualToPhysical. Вызов controller
ветки или MIPS break останавливает стенд.

Проверены заголовки type5/type6, размеры2×2/64×32/320×240, оба банка и alpha0/128/255.
При неизменной картинке строятся802 дополнительных списка команд с time-based Fade
на60/73/144/165/360FPS; отличающихся alpha больше16, то есть исходные20Hz кадры
не просто повторяются. Проверяются target framebuffer/depth и наличие texture rect.
После каждого draw+fade сравниваются все4MiB RAM, кроме записанного DL, cursor и
256байт стека: hold/transition, прочие счётчики, ресурсы, framebuffer и соседний
банк должны совпасть. ASan/LSan пройдены. Это проверка побочных изменений и команд,
а не визуальная оценка изображения или поддержка всех форматов текстур.

При подготовке стенда исправлены неверно указанный адрес rgba_rectangle
(правильный80028688) и отсутствовавшая заглушка do_break. Игровые функции ради
прохождения проверки не менялись. Отчёт: research/native-scene34-draw-check.json.

## Следующая интеграция — ещё не реализована

Для первой ограниченной активации подходит image-ветвь до перехода к белому fade.
Нужны: подтверждённый init/поколение overlay, стабильная пара process slots в state2,
проверка отсутствия других active callbacks и переходов, снятый pause и Manual.
Проверки одних callback-адресов недостаточно из-за наложения overlay адресов.

Вход разрешается после исходного update на20Hz, окончания legacy задач в ОБОИХ
внешних SP/DP callers и принятия их сообщений, затем через PresentationGate.
Пока идут Acquiring/Draining, нельзя строить Original кадр или менять scene/resources;
completion должны продолжать приниматься. Один guest outstanding==0 не доказывает
legacy retirement, как показало исправление v65.

В Native дискретные input/repeat/hold и VI/audio остаются на исходном времени;
fade обновляется по elapsed перед каждым собственным построением команд. Исходный
fade_tick нельзя выполнять одновременно. Общий graphics_frame_build8002FF64
требует отдельной проверки: он меняет transition state801A48E0 и вызывает dispatcher
с состояниями callbacks. Чистота отдельного image draw не доказывает чистоту build.

Перед hold1→0 нужно прекратить новые native кадры и дождаться drain, только затем
разрешить transition801BFDE0/белый fade и следующую3D-сцену. Переключения Manual,
Original и pause также должны проходить этот путь. До сквозной проверки этих границ
новый пользовательский EXE не выдан; test-024 не менялся. Android/GPU не проверялись.
