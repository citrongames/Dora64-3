## Реализация и проверка

- Запрос новой функции означает реализацию целиком, если пользователь не просит
  только анализ. Существенные неоднозначности уточнять; обычные решения принимать
  самостоятельно. Учитывать Original и Native/Manual FPS.
- Игровую логику изучать по оригинальному коду и ROM; не угадывать адреса и роли.
  Проверять связанные аналогичные пути. Генерируемый код вручную не редактировать:
  править исходники, генератор или адаптеры. Сохранять семантику времени, команд,
  событий, коллизий и владения ресурсами.
- Тесты, CPU checks, автоматические прогоны, игру, эмулятор, renderer и GPU
  **не запускать**. Разрешены статический анализ, необходимая генерация,
  компиляция и упаковка. Игровую проверку выполняет пользователь.
  Успешная компиляция не подтверждает поведение или FPS в игре.
- После законченной реализации/исправления сразу одна инкрементальная Windows
  сборка: это постоянное разрешение пользователя от 2026-10-10. Номер брать
  по существующим EXE в `D:\Games\DoraRecomp3\testbuild`. Для чисто документальных
  и Git-изменений пересборка не требуется. Полная пересборка — только по причине.
- Сохранять старые EXE, ROM, настройки, сейвы, общие DLL и пользовательские assets.
  Не повторять проверки неизменённых частей. Чистые сборки без диагностики и
  профилировщика; диагностический режим — только для согласованного расследования.

## Git и библиотеки

- Коммит и push — после проверки пользователя и его явной команды. Работать
  в существующей `main`; не создавать новые ветки, не переписывать историю,
  не менять приватность и не публиковать релизы без просьбы.
- `/home/vova/projects/Dora64` и справочные `sources/` только читать.
  Не менять их исходники, Git, библиотеки, настройки и сборки.
- Версии библиотек задаёт `dependencies.lock.json`; их отдельные checkout
  находятся в игнорируемом `build-deps/`. Адаптеры Dora64-3 создают копии
  исходников в build-directory. Не переносить их в общие форки автоматически.
- Не обновлять dependency HEAD, gitlinks или lock ради уборки. Не использовать
  `submodule update --remote`, общие checkout, Git alternates или hardlinks
  с первым портом. Перенос исправлений в Dora64 требует отдельного поручения.
- ROM, извлечённые оригинальные ресурсы, генерируемый C/RSP, сборки, сейвы,
  логи и ключи остаются вне Git. Авторские переводы, шрифты, рисунки, метаданные
  и воспроизводимые адаптеры остаются в Git. Сохранять upstream notices/лицензии.
